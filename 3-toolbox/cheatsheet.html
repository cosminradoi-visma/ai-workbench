Six safety rules

  1. Never customer data, sensitive personal data or secrets. Restricted only with written approval.
  2. Company account only. No personal Pro/Max for work.
  3. You own what you merge. Can't explain it? Don't ship it.
  4. Read before you install: kb-vet.
  5. Never private data + untrusted content + a way out in one session.
  6. Must-hold rules go in settings and hooks, not prompts.

Ten tips

  1. /context once per repo: see what you pay for.
  2. /clear between tasks; after two failed fixes, clear and re-ask.
  3. Give it a check to run: tests, a script, a URL.
  4. Shift+Tab plan mode for anything multi-file.
  5. Write only what the agent would get wrong.
  6. @import loads at launch; it saves nothing.
  7. Second time you explain it → make it a skill.
  8. A fresh-eyes reviewer catches what the author rationalised.
  9. Don't switch model mid-task: cold cache.
  10. Golden tasks: /golden-run → passes and cost.

If something goes wrong

  • Secret leaked: rotate now, then tell security. Deleting the commit isn't enough.
  • Banned data went in: stop, keep the conversation, report the same day to your DPM or security. Personal data → security@visma.com.
  • Agent did something odd: Esc Esc to rewind; add a line to learnings.md and a check to the guard.
